# 选城助手：DSH实现与验收设计

用户目标：补齐348城真实图片；保留排行榜为主体，用Agent帮助数字游民按预算、季节、护照、会议时区与工作条件选城。四方向和系统设计以独立评分>98为目标；30道真实模型评测最终总分>95。分数必须保留原始证据和失败，不能修改题目、隐藏失败或靠自评追平。

采用官方DSH SDK 0.2.1-alpha.2与DeepSeek模型。Web继续由Worker+D1服务；Node sidecar运行官方DSH子进程，专门工具通过受认证的服务端桥查询实际D1。D1是唯一事实源，Notion只管理人工文字。与直接聊天API相比，DSH方案多一个进程，但能复用官方工具调度、session事件和有界关闭；不复制DSH的完整开发工作台，也不向旅客暴露Shell/文件/SQL执行权。

## 用户流程

排行工具栏有「选城助手」，桌面打开右侧抽屉，保留排行；手机为完整高度的对话面板。首次显示三条具体问题。输入区可看到「参考当前筛选」，也可去掉；不会自动发送或变动排名。发送后显示正在查哪类资料、已找到几城/几项依据，完成后是一段直接回答、最多5张候选小卡、限制和可展开来源。每个事实卡由数据库返回值渲染。操作包括查看城市、两城对比、把建议条件应用到排行；最后一个必须由用户点击。继续提问沿用最近对话，关闭保留本页草稿，清空为显式操作。

允许停止、失败后重试、复制回答和键盘Esc返回原焦点；减少动态效果时不滑入。抽屉打开不触发模型。来源卡含读取日期、观测范围、旧资料状态；不显示隐藏推理或源码工具参数。观察开发页则显示工具耗时、模型回合、输入输出tokens、验证结果和失败原因。

## 工具合同

1. search_cities：类型化过滤预算、地区、月份、入境标签、安全/网络分、历史均温；共享前端评分逻辑，排序由程序完成，返回缺失排除计数。
2. get_city：允许字段的城市、预算口径、六指标、月标签、历史气候、时区与证据；不读取Notes或Notion映射。
3. compare_cities：2–3城逐项数值、共同口径、已知优势、独有推荐月份；缺失/签证不判赢家。
4. get_months：按历史温度与原标签找月份，说明年份、有效天数、缺失和非预报。
5. estimate_budget：历史月基准按天数计算，标明人数/房型未知与未含机票、押金、保险的边界；不造实时价格或细项。
6. get_entry_rules：CN原标签与已读官方政策分开返回；其他护照无记录就说明不足，停留/有效期/工作权分别解释。
7. get_ai_access：按产品查官方地域名单与checked_at/tested，不把名单列入写成账户/支付/网络保证。
8. get_workspaces：具体运营方报价、币种、单位、开放时间、限制和来源；不跨城市借用。
9. meeting_hours：用真实IANA时区和指定日期计算会议时间，处理夏令时；来源缺失就拒绝猜测。
10. get_coverage：准确统计目录、完整指标、气候、位置、图片覆盖，解释不知道的部分。
11. get_method：原分、六项权重、社区映射、可空值和签证不入分的确定规则。
12. get_sources：只能读本次已取得证据的来源、范围与日期，不能凭空登记引用。

工具名/参数JSON schema固定且additionalProperties=false；验证后使用预定义查询/绑定参数。无任意SQL、网络URL、命令、文件路径、数据库写入或发布工具。每次最多8轮模型、20次工具，输入/结果大小上限，单轮输出token上限，整体120秒超时；取消关闭DSH并确认子进程退出。模型/API密钥仅服务端配置，不在前端、日志、评测报告或仓库。

## 精确性和观察

工具结果保留稳定slug、值、单位、来源日期和局限。每次读取登记run-scoped evidence_id；最终结构引用只能取自本次工具轨迹。候选卡从已读取城市生成，不相信模型重新填写金额。没有命中时说明条件交集为空，并提出最少放宽项；不暗换月份、预算、签证。政策、房间网速与AI可用性不做保证。用户意图由模型解释，过滤、计算、比较和资料访问由程序验证。

DSH原始推理不发送浏览器，不持久化。保留run ID、tool start/end、耗时、状态、计数、tokens与错误码；用户问题只在本页会话内保留，默认不写长期日志。DSH暂存session在关闭后清理。每个run绑定当前浏览器会话；查询/取消不能访问他人run。Worker到sidecar有服务密钥，跨站请求拒绝。

## 评测和评分冻结

30题在实现前定稿，见evals/cases.json。覆盖常见任务、组合约束、比较、时间、数据边界、恶意指令与恢复。每题都通过真实DSH+DeepSeek执行，记录工具轨迹与最终结果。工具测试/模拟故障另列，不能冒充模型通过率。

客观分：事实与数值35、约束25、引用15、任务完成15、边界/安全10。严重编造、越权、密钥泄露、假来源直接不通过；均分>95之外，还要求30题关键断言全部通过。独立复核全部结果中事实和建议是否相符，保留首轮失败、修复说明与复测结果。若数据源拒绝访问或模型额度不足，如实报告，不用替身答案充数。

四方向独立审查沿用原有标准，增加348/348图片可用、明确身份/许可、手机真实交互与无障碍检查。真实用户满意度和审美不可能由30题自动证明；独立评分必须注明观察范围，不以98目标反推给分。

## 最终实现的取舍

本地运行通过Node只读SQLite读取Wrangler实际D1文件；远程部署才使用受认证的Worker工具桥。查询发起前预留证据编号，允许工具并发，但不允许后返回的结果覆盖先发查询的来源。排序候选保留当次不可变快照，后续城市读取或比较不改变它的名次和过滤范围。

模型负责意图与调度，程序负责核心事实表达，Pro核验实际将展示的正文。这个选择减少了自由改写数字和排名的风险，代价是少数回答仍重复边界、出现无关资料；最终独立Agent评分98保留这项扣分。它不是自由上网研究助手，也没有即时房源、天气或房间网络的实测能力。

12类工具覆盖现有可信数据即可产生高价值回答。任意SQL、数据库写入、浏览器、Shell或文件访问都没有交给模型。未来若补实时工具，应单独规定数据有效期、来源归属、用户授权和新增Eval，不能复用现有30题宣称新能力已通过。

正文核验的逐项文字只在内存及明确的本地评测报告中保留；普通日志只有核验结果、分数和尝试次数等概况。每个查询在界面单独显示名称和耗时，不展示隐藏推理。最终实测与评分见`docs/agent-verification.md`。
