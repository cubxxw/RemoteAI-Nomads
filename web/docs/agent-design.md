# 旅行小秘书：让工具支持推理

> 本文保留早期 DSH 对照设计。正式网站采用原生 DeepSeek Flash，当前架构、限额和发布流程见[部署说明](deployment.md)，小狐界面与本地历史见[旅伴设计](companion-design.md)。

本次修正针对真实失败：“一月去，预算2000人民币，中国区”被旧系统误当成亚洲、严格281美元月参考价筛选，得到空结果和一长串警告。旧30题通过不能证明这个使用路径正确；原报告保留在history，不能沿用旧Agent98分作为当前质量结论。

## 分工

提示词只定义角色、解决问题、必要查证、引用与假设、延续对话和提交方式。具体单位、范围、参数放在对应工具说明。金额与排序由工具算，模型自由组织有用的回答；已删除覆盖正文的固定模板。参考消费只能帮助比较，不能推出用户预算的最低下限。

正式助手通过 Workers 原生 HTTP 循环调用17类领域工具，规划和分离核验均使用 DeepSeek Flash。finish_plan 接收结构化草稿，不产生事实证据；submit_check 接收完整断言的逐项核对。SQLite Durable Object 管理会话，单次工具经独立内部请求访问 D1，以免长对话累积耗尽单次查询额度。原始 reasoning_content 仅在服务端回传模型，不进入公开追踪。DSH 与本机 codex-local 仅保留为历史对照，未部署到正式后台。

| 用户要做的事 | 工具 |
| --- | --- |
| 找候选、核对目的地和月份 | search_cities、get_city、get_months |
| 看实际分项和不同方案 | get_costs、convert_currency、explore_budget_options、plan_budget、recalculate_budget |
| 两城取舍、旧口径计算 | compare_cities、estimate_budget |
| 远程工作与停留 | get_workspaces、meeting_hours、get_entry_rules、get_ai_access |
| 理解资料覆盖和来源 | get_coverage、get_method、get_sources |

预算工具验证用户或模型明确列出的规划假设，输出余额与缺口，不把输入数字包装成真实报价。消费工具保留城市样本、全国统计、单位、日期、质量标记和国内覆盖，不能用某城无样本推断全中国无资料。旧月总额默认不提供，只有明确读取旧参考或复现旧筛选时才返回。

低预算的第一步是比较约束，而不是挑一个餐费后把住宿上限说成所有人的必要阈值。explore_budget_options在同一预算、币种、天数与预留下，验算2至6组明确的非住宿支出假设，并列住宿余款上限。例如2000元/30天、自设餐20元/天，住宿上限46.66元/晚；自设餐15元/天，上限51.66元/晚，所以第一种情景不能证明50元床位必然超支。这里的15/20/50都是反例假设，不是已找到的餐食或房源。

工具给出青旅床位、合租房间、独立房间、整租住房四种待核查方向，全部标记未验证供给和价格。它没有穷举城市全部消费方式，也没有抓取日期对应的住宿库存；条件算术成立和实际成行仍有距离。get_costs同时返回住房样本范围和旧总额存在性，默认不暴露旧金额，避免造成价格锚定。

日本全国单身家庭消费总额已经包含住房。工具分别给出总额、住房、非住房派生值；全国参考不能一键填成东京房租。只有合格城市挂牌月租可以由用户主动采用；异常报价待复核，不作为低价承诺。

## 交互

入口“旅行小秘书”；桌面侧面板、手机全高面板。城市页入口预填本城问题，不自动调用模型。回答支持短表格、清单和可点击的[E1]依据。候选卡只是目的地入口，不再把旧美元月价贴在人民币方案旁。

用户改变一个条件时保留已经确认的其他条件、单价和预留金；缺失信息先给工作假设，再问关键问题。界面可停止、重试、复制、清空；草稿只在当前页面内存中。

预算快照保留原始amount/period及住宿分配。多情景不默认确认末条，用户点击“沿用这组”才采用相应原始假设；选择不调用模型。recalculate_budget仅改天数时按原单位重算；明确重分配才改变住宿上限。真实浏览器已验证2000元/30天、餐600/月+交通200/月+杂100/月、住宿1100分配，改15天后分别300/100/50/550，合计1000、余额1000。未把显示时四舍五入的日价当原始金额，也未默认把余额投入住宿。

## 保留的工程边界

模型没有SQL、文件、Shell、任意网址或写库工具。数据库访问、计算、引文归属与城市卡来自同次证据；来源不能包含可执行指令。原生草稿保存版本，核验相同版本后才展示；不以模板覆盖自由回答。

规划与核验分别留模型调用额度，最多规划12次、核验6次、工具20次、整体180秒。原生模式停止、断连及完成都会关闭主任务与模型请求，并阻止后续数据查询；没有容器进程或临时目录；配额等待期间已断连的请求不会稍后启动模型。限额、超时和事实核对失败显示不同反馈。

核验先找结论和建议中的实质反例，不以模型自报100分当事实证明。统计范围、重复计入、均价与最低价、旧评分与历史气候均纳入反例测试。最终质量仍需逐份独立复核；自动通过不是正确率保证。

正文、表格和公式按连续原句组成至多24组核验项，不按关键词丢弃尾部。submit_check只返回唯一claim_id、依据与是否成立，原文由服务端绑定，不能把半句改写为核验对象。该机制修复覆盖和提交协议，不证明推论真实；实测模型仍可能用正确的前提支持过强结论。主提示保持两段，具体单位与边界放在工具数据中。当前规划为 deepseek-flash/low，分离核验为 deepseek-flash/none；codex-local 只保留为旧版的本机实验。

普通日志只留计数、耗时、用量和核验状态，不存用户正文或隐藏推理；明确的本地评测才保存问题、回答、原始工具快照与核验意见。
