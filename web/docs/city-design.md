# 城市页：从一座城市，走到自己的生活计划

城市页先让人认识地方，再回答「花钱在哪、几月去、工作日怎么安排」。真实城市照片承担第一眼，城市名、英文名、国家、城市短句和标签叠在照片下半部。沿用现有品牌的纸色与森林绿，保留收藏、对比、分享；分享继续使用全站原有的入口与隐私边界。

照片下方先读三项决策信息：历史月花费、所选月份的历史均温、与北京的工作时差。均温旁直接标出 2023–2025 的统计期，花费保留历史参考的性质；推荐月份和入境标签紧随其后。均温随原月份控件联动，时差仍随会议日期与小时联动。

有公开城市风貌资料时，先展开地理位置、人口、语言与货币、具名地标、地方生活和吃食，再进入原有的预算与工作工具。人口年份和行政范围紧靠人口值；坐标的参考点性质也在就近位置说明。其他资料口径、核对日期、引用和照片署名收在原生展开控件中。没有风貌资料就保留原有城市简介与全部工具，不生成地标、不借用邻城内容，也不填一排空字段。地标目前只用已收录的文字，不拿城市封面冒充特定景点照片。

城市印象、生活预算、出发季节、远程工作、工作地图、停留入境使用页内导航，滚动时更新当前位置。桌面侧栏提供计划入口和订房提醒；手机把这些安排放到正文之后。窄屏将三项决策信息变成两列加一行，正文按地理、人口、地标、生活的顺序逐项展开。

设计判断采用“网格与字阶”和“成品审查”：照片、城市名、关键数字各有明确位置；地标用编号、标题和正文建立阅读节奏。预算继续用轻底色表达可编辑区域，价格、气候和工位依内容排列。资料不能因追求留白而丢失；大图也不能代替预算、气候与时差的真实操作验收。

## 城市风貌与实现边界

页面消费经过 `normalizeCityProfile` 校验的 `c.profile`，由 Worker 从同源 `city-profiles/<slug>.json` 读取，故无脚本时仍能阅读。资料缺失或读取失败不影响页面和计划工具。`city-profile-invitation.js` 只将原有月份事件同步到首屏均温，不新增请求、不保存其他个人资料、不改变原预算和会议状态结构。

2026-10-27 本轮本地模块验证：城市页与渲染测试 27 项通过。新增检查覆盖风貌信息和人口范围保留、缺少风貌资料时的回退、请求月份的首屏均温，以及预算、月份、会议、地图和入境入口保留。存在官方出行提醒的城市使用中性风貌标题和侧栏，提醒置于大图之前，不作住游邀请。

本轮实际 Chromium 预览检查了博卡拉 390 / 1440 px 的首屏与城市风貌正文，两个宽度均无页面横向溢出；真实封面图成功读取，分享入口只有一个。将月份从 11 月选为 12 月后，首屏和图表均温同步从 17°C 改为 14°C，浏览器无脚本错误或警告。截图位于 `output/playwright/city-invitation/`。这些是本地画面与月份联动记录，部署状态、完整计划流程和真实出行条件仍须各自确认。下方 2026-10-18 的记录属于此前版本。

## 交互与证据边界

消费数据读取 `readCityCosts`。城市页先展示单人、30天的开销参考和现有消费样本，计算器默认收在“按我的报价调整”中。首屏直接显示已知开销小计、未计入项目及修改入口。住宿采用合格一居室月租挂牌样本，优先中心区外；单人平价餐按每天3顿估算，公共交通优先采用月票，没有月票时按每天2次单程票，手机套餐按月。数量是明确写出的规划假设，不是供应商提供的完整旅行预算。

默认值仅采用有可用人民币换算的本城CostCompass样本。全国居民支出、区域监测、多人餐、三居室或85平方米水电不自动带入。待复核住房、非月租和缺少挂牌标记的住房也不预填。其他日常开销默认留空；缺项在概览和计算结果旁直接显示，填写0作为用户明确假设。原币、样本日期及来源保留在消费参考中。旧城市月成本继续作为历史记录，不用来倒推各项价格。

用户可选择停留天数，展开修改每项报价、采用下方合格住房样本或恢复本城默认参考。月支出按30天折算仅作规划估算，不是短租报价。人民币、美元、日元切换以内部人民币金额为基准，避免反复换币累计误差；界面注明哪些是样本推算、哪些由用户调整。往返交通、押金、保险及签证费用需要另行核对，小计不冒充完整旅行总预算。预算与报价编辑本身不会调用模型。

可选的总费用上限与已知开销小计计算余额，并就近提醒缺项和往返交通等费用。报价、上限、月份和会议安排只保存在本机。用户原币报价与换算快照分别保留；参考资料更新时更新参考值，明确清空的项目继续留空。未完成金额不会覆盖上次有效报价。

季节区域有全年均温曲线和月雨量柱。选择月份后，均温、降雨、季节标签和图中位置一起更新。缺失温度与真实 0 mm 降雨分别处理。源数据表、历史采样口径和来源放进原生展开控件。

会议工具以用户选择的上海会议日期和小时为起点，通过城市 IANA 时区计算当地时间，处理目的地夏令时和跨日。未记录时区时不猜测。AI 官方地域名单、工位报价限制和政策全文均按主题展开。“检查这份预算有没有漏项”入口预填本城、当前月份、天数、币种及五项开销，区分默认推算、用户修改和未填项目；用户确认发送才调用模型。预算和日历交互本身不触发模型。

标题、canonical、Place JSON-LD 和草稿 noindex 沿用现有外壳。没有 JavaScript 时，参考价格、默认月份气候、默认会议时差和原生来源展开仍可使用。
