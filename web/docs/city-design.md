# 城市页：一份可以拿来计划的目的地指南

城市页先回答「这个地方怎么样、花钱在哪、几月去、工作日怎么安排」，再提供可展开的来源。它沿用排行页的中性色与森林绿，不另起一套品牌。

页面从真实城市照片开始，接四项简明事实：本城消费样本数、原推荐月份、入境标签、当地时区。生活预算、出发季节、远程工作、工作地图、停留入境使用页内导航，滚动时更新当前位置。桌面侧栏只保留城市自己的提醒和旅行小秘书入口；手机将提醒放在正文之后。

设计中最醒目的部分是城市照片，其余地方让信息本身建立层级。首次审图后删去了城市页原有的统一提示块与大段说明。预算使用一块轻底色来表达可编辑区域；价格、气候和工位按内容排列，避免将它们做成同样大小的装饰卡片。

## 交互与证据边界

消费数据读取 `readCityCosts`。城市页先展示单人、30天的开销参考和现有消费样本，计算器默认收在“按我的报价调整”中。首屏直接显示已知开销小计、未计入项目及修改入口。住宿采用合格一居室月租挂牌样本，优先中心区外；单人平价餐按每天3顿估算，公共交通优先采用月票，没有月票时按每天2次单程票，手机套餐按月。数量是明确写出的规划假设，不是供应商提供的完整旅行预算。

默认值仅采用有可用人民币换算的本城CostCompass样本。全国居民支出、区域监测、多人餐、三居室或85平方米水电不自动带入。待复核住房、非月租和缺少挂牌标记的住房也不预填。其他日常开销默认留空；缺项在概览和计算结果旁直接显示，填写0作为用户明确假设。原币、样本日期及来源保留在消费参考中。旧城市月成本继续作为历史记录，不用来倒推各项价格。

用户可选择停留天数，展开修改每项报价、采用下方合格住房样本或恢复本城默认参考。月支出按30天折算仅作规划估算，不是短租报价。人民币、美元、日元切换以内部人民币金额为基准，避免反复换币累计误差；界面注明哪些是样本推算、哪些由用户调整。往返交通、押金、保险及签证费用需要另行核对，小计不冒充完整旅行总预算。预算与报价编辑本身不会调用模型。

可选的总费用上限与已知开销小计计算余额，并就近提醒缺项和往返交通等费用。报价、上限、月份和会议安排只保存在本机。用户原币报价与换算快照分别保留；参考资料更新时更新参考值，明确清空的项目继续留空。未完成金额不会覆盖上次有效报价。

季节区域有全年均温曲线和月雨量柱。选择月份后，均温、降雨、季节标签和图中位置一起更新。缺失温度与真实 0 mm 降雨分别处理。源数据表、历史采样口径和来源放进原生展开控件。

会议工具以用户选择的上海会议日期和小时为起点，通过城市 IANA 时区计算当地时间，处理目的地夏令时和跨日。未记录时区时不猜测。AI 官方地域名单、工位报价限制和政策全文均按主题展开。“检查这份预算有没有漏项”入口预填本城、当前月份、天数、币种及五项开销，区分默认推算、用户修改和未填项目；用户确认发送才调用模型。预算和日历交互本身不触发模型。

标题、canonical、Place JSON-LD 和草稿 noindex 沿用现有外壳。没有 JavaScript 时，参考价格、默认月份气候、默认会议时差和原生来源展开仍可使用。

- 里斯本 2027-01-15 上海 09:00 对应当地 01:00；2027-07-15 对应 02:00。纽约同年 1 月上海 01:00 对应前日 12:00。
