# 押金之外的占用：预授权、冻结与保证金怎么区分

这篇适合谁：适合经常住酒店、订长租房、在平台下单时被要求先付一笔或先冻一笔，却分不清这笔钱找谁退、何时退的人。如果目前只用现金支付、没有信用卡或平台订单，这篇可以先看最后一节的记账方法。

先把三类信息分开。事实部分只讲三种占用分别由谁控制、释放路径有什么不同；假设部分不设统一时限，因为不同银行、平台和租约的规则并不一致；建议部分只给分类方法和核对动作。凡涉及银行处理规则和平台退款规则的地方，本文只教怎么查、向谁确认，发布前需按官方来源复核，不按本文直接判断某一笔占用应该在哪一天释放。

很多人把所有先付或先冻的钱都叫押金，其实至少要分成三种：酒店或租车场景里的预授权、交易平台里的保证金、租房合同里的押金。三者的共同点是钱暂时不能自由使用，不同点是控制方不同。分类的标准只有一个：这笔钱现在由谁控制，释放要满足什么条件，出问题时应该找谁。按这个标准对号，后续的等待、催办和记账才不会找错对象。

## 预授权是银行层面的额度占用，释放要等银行处理，催商家解决不了

预授权常见于酒店入住和类似需要担保的消费场景。它占用的通常是信用卡可用额度或账户可用余额，商家发起占用，实际释放由发卡银行或支付机构按其处理流程完成。商家完成结算或确认取消占用，只代表商家一侧的动作已经结束，不等于额度在同一时刻回到账户。

所以遇到预授权迟迟没有释放，先分两步核对。第一步向商家确认：这笔占用是否已经完成结算、撤销或结清，确认时留好订单号、确认时间和对方给出的处理说明。第二步向发卡银行确认：在银行的应用或账单明细里找到这笔占用记录，核对占用日期、金额和当前状态，再问银行一侧的释放进度和查询路径。只反复催商家、却不向银行确认状态，容易在两个环节之间来回转。

核对时不要凭记忆估时限。不同发卡银行、不同卡种和不同交易类型的处理方式可能不同，本文不列统一天数。需要判断是否异常时，以发卡银行当期公布的规则和客服针对这一笔交易给出的记录为准，发布前需按官方来源复核。自己能留的证据是三样：商家确认已处理的时间、银行明细里的占用记录、与银行沟通时得到的查询编号或回复记录。

## 平台保证金跟着订单状态走，退不退和何时退先看平台规则原文

平台保证金与预授权的区别在于控制方。保证金通常由平台按订单规则收取或冻结，释放条件写在平台规则和订单详情里，与订单是否完成、是否取消、是否有争议、是否通过验收等状态直接相关。订单状态没有走到规则里写明的那一步，保证金就可能一直处于待处理状态，这时找银行通常解决不了，因为银行不是这一笔保证金的规则制定方。

处理顺序是先看订单，再看规则，最后才联系平台客服。先打开订单详情，确认当前状态是待完成、已完成、已取消还是争议中，并截图或保存状态页面。再回到下单时适用的保证金说明，逐项核对释放条件、申请入口和处理说明，不要只看其他用户的经验帖。联系平台客服时，把订单号、当前状态和规则里对应的条款一起提交，问题要具体到这一笔订单卡在哪一个状态，而不是只问保证金什么时候退。

还要区分保证金和平台预付的房费或服务费。预付费用是已经支付的消费款，退款走消费退款规则；保证金是为履约作担保的占用，走保证金释放规则。两者在账单里可能挨得很近，记账和追踪时要分开标，不要合并成一笔平台支出。涉及平台当期规则的具体表述，发布前需按官方来源复核，下单前也应以平台在付款页面展示的当期说明为准。

## 房东押金是合同层面的占用，退多少和何时退回到租约与交接记录里核对

房东押金既不由银行按预授权流程释放，也不由平台按订单状态释放，它的依据是租约约定和退房交接结果。押金金额、扣除项目、退还方式和退还时间，首先看签约时双方确认的文本，其次看入住和退房时留下的房屋状态记录。没有这两类材料，争议就容易变成各说各话。

这部分的具体处理方法见《退房时押金被扣：哪些扣款要凭证，哪些在入住时就能预防》，那篇专门讲哪些扣款应该要求凭证、哪些问题可以在入住时通过拍照和清单提前预防，本篇不重复展开。本篇只强调分类上的一点：房东押金出问题时，沟通对象是房东或签约中介，依据是租约和交接记录，不要套用预授权找银行或保证金找平台的路径。

签约前要把押金条款单独圈出来核对：押金对应几个月的租金或固定金额、什么情况下可以扣、退还通过什么方式、退还以退房确认后的什么动作作为起点。这四项如果租约里没有写清，要在付款前用文字补充确认，不要等退房时再商量。付款后把押金付款凭证与租约放在同一个文件夹里，方便退房时直接对照。

## 记账时把占用单列一行，不计入支出，可用余额要先扣掉占用

三种占用在记账时用同一种处理：单列，不算支出。占用不是已经消费掉的钱，把它记成支出会让月度开支虚高；完全不记，又会高估手头能用的钱。最低做法是在账本里加一个占用类科目，每笔占用一行，写清类型、对象、金额、币种、占用日期、预计核对日期和当前状态，释放后再把状态改成已释放并标注日期。

科目设置可以接《多币种记账：一个月对一次账的最低科目表》的结构，在那张最低科目表的基础上只加占用这一类，不需要为每一种占用单独建一套科目。类型字段写预授权、平台保证金或房东押金即可，这样月末对账时既能看到总占用金额，也能按找谁退快速分组。

现金流排期时，占用必须算进可用余额的扣减项。这一点与《预算表里要留一行汇率：收入是人民币、支出是外币时怎么留缓冲》是同一套排期逻辑：账面余额减去尚未释放的占用，再减去已确定的待付支出，剩下的才是下一段行程能动用的钱。举例来说，示例假设：账面余额一万元，其中酒店预授权和房东押金合计占用三千元，那么排期时按七千元可用计算，而不是按一万元计算。这个示例只演示算法，金额是示例假设，不对应任何真实订单。

## 收尾清单：每出现一笔占用就按控制方归类并留一条记录

- [ ] 先分类：这笔钱属于预授权、平台保证金还是房东押金
- [ ] 记控制方：银行、平台还是房东，出问题时只找对应的那一方
- [ ] 留凭证：订单号或租约、占用金额、币种和占用日期已保存
- [ ] 查规则：释放条件已按银行或平台的当期官方说明核对，房东押金已按租约核对
- [ ] 单列记账：占用已单独记一行，没有计入当月支出
- [ ] 扣减余额：现金流排期时已从可用余额里扣掉尚未释放的占用
- [ ] 跟状态：超过自己设定的核对日期仍未释放时，已按对应路径再次确认
