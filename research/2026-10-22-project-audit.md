当前项目是面向中文远程工作者的旅居选择指南。它的价值在于把“能否工作、适合谁、成本口径和现实代价”连在一起。本轮先改善阅读路径、证据可追溯性与维护检查，保留 Markdown + JSON 的轻量结构。

## 审查范围与方法

三个 sub-agent 分别审查数据、读者路径及动态事实；另两个独立实现数据与链接检查器。协调者核读官方页面、整合修改并安排独立复审。检查覆盖 27 个主目的地、167 条来源、18 条费用观察，以及 README、地区指南和来源账本。

本地结构检查与外部事实复核分开：没有实测住宿网络，没有验证指定日期空房，没有重新读取全部社交原帖或完整核验所有签证条件。搜索摘要不按全文核读处理。

## 数据改动及兼容性

城市数据版本从 1 升为 2。价格增加的两个字段属于必填溯源字段；旧消费者应检查版本后再读。没有修改原金额、币种、计价周期、原帖日期或报价核读日，也没有新增城市总预算。

18 条价格中，6 条按 `published_on` 对应原帖日期，12 条按 `checked_on` 对应运营方报价核读日。`null` 总预算仍表示缺少可比数据，空费用数组仍表示没有可用观察，零元仅保留明确免费的白天工位。

27 个主记录之外，大叻、班斯科及国内三城仍是待补证线索。`recommendation_for` 表示评估覆盖期，不是可直接用来筛选入住月份的数据。IANA 时区继续保留，避免冬令时切换时固定偏移失真。

来源文件名与顶层获取日保留 10 月 14 日批次身份，城市数据编辑日为 10 月 22 日。来源用途 `used_with_limits` 只说明如何使用证据，不等于“今天已重新核实”。

## 接下来最值得做的六件事

1. **先补首页六个候选的可比住房样本。** 统一入住日期、人数、房型、租期，记录最终账单、水电、押金、办公与通勤。成功标准是每城能填完同一张比较表；没有报价继续留空。
2. **逐项管理政策复核日期。** 对入境和远程工作条件补对应护照、官方法条和有效期；优先补巴西备用全文与临时措施。`review_after` 是维护计划，官方 `valid_until` 应另存，不能混用。
3. **持续保留证据历史。** 下一轮新采集建立新批次或独立复核记录，避免反复覆写 10 月 14 日账本。当前已拆清旧评论日；将来再决定是否统一来源索引。
4. **用一次真实工作周补可信体验。** 先选读者最常问的一城，记录同一房间的会议、热点备线、停电后网络和夜间权限，再发布实测。测速地点与时段比全城“网速评分”更有用。
5. **逐家补国内社区现状。** 先从大理、安吉、黄山各一处开始，取得当前运营入口、房型、收费和工作条件；达到主记录标准后再结构化。
6. **数据完整后再做比较页面。** 第一版只比较时区、适用月份条件、服务范围和证据日期；缺预算时明确缺失，不按工位起价排序，不生成缺依据的综合分数。是否建设网站留待实际阅读需求确认。

## 检查与维护

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_data.py --as-of 2026-10-22
python3 scripts/check_links.py
git diff --check
```

数据检查拒绝坏结构、无效引用、非有限金额、错误日期关联和无效时区；链接检查验证本地文件与常用 Markdown 锚点。链接解析器明确只支持仓库常用语法，不承诺完整 CommonMark；外部网页不由离线校验判断。

O01、O02、O03 的旧天气/灾情快照已过原复核日，会保留提醒。首页的泰北新预报已另标日期，不把旧 JSON 快照伪装为新读资料；岘港当前现场仍待复核。

本地结果：Python 3.10.11 下 **45 项回归测试通过**；数据检查覆盖 **27 个目的地、167 条来源**，仅输出上述 3 条预期提醒；链接检查覆盖 **15 份 Markdown，0 个本地链接错误**；`git diff --check` 通过。另与修改前数据逐项对比，原价格字段、总预算、来源 URL、发布时间、获取日、读取范围和用途均保留。

独立复审没有发现重要阻塞问题；另外补齐强调标题和转义路径的解析回归，并将 CI 空白检查改为检查实际提交。两项修复均经限定复审确认，未发现新引入的重要问题。临时 Git 仓库以深度 2 检出验证：干净提交通过，普通提交与合并提交中引入的尾随空白均被拒绝。完整 CommonMark、HTML 注释和多行链接仍不在本地解析器的保证范围内。

CI 文件已配置 PR、push、手动和每周一 01:17 UTC 运行。每周调度需工作流进入默认分支后生效，且可能受平台调度延迟影响；依据 [GitHub 官方事件说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。本轮没有推送、合并或执行 GitHub 云端工作流，不能把本地通过写成远端通过。
