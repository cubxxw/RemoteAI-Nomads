# 可复用的旅居数据

[destinations.json](destinations.json) 存城市选择、季节窗口、时区、适合的人、现实代价和费用个案。[sources-2026-10-14.json](sources-2026-10-14.json) 存对应公开来源的时间、读取范围和中文编辑摘要。

本页供读取数据和维护记录使用。规划旅居请从[城市索引](../guides/destination-notes.md#destinations)与[比较模板](../guides/choose-a-base.md)开始；提交纠错不要求先理解所有字段，可直接用[投稿模板](../CONTRIBUTING.md#投稿模板)。

## 版本与文件

城市数据当前 `schema_version: 2`，来源数据仍为 `schema_version: 1`。相对城市数据 v1，每条价格新增必填的 `source_id` 和 `source_date_kind`；下游使用者应先检查版本。`updated_on` 是城市数据编辑日，不代表全部资料在这一天重新核实；来源文件名与顶层 `retrieved_on` 保留最初采集批次日期，各条以自己的核读字段为准。

## 费用字段与空值

`source_ids` 对应来源文件中的 `id`，同一城市内不重复。`price_observations` 是有条件的费用观察，每项保留币种、时间单位、来源日期和包含范围；办公会员、房租和共居套餐不能直接横比，也不能把起价相加当成保证可预订的生活预算。

| 价格字段 | 含义 |
|---|---|
| `source_id` | 直接证明此价格的来源，必须同时属于本城市的 `source_ids` |
| `source_date_kind` | `published_on` 为原帖日期，`checked_on` 为公开报价核读日期 |
| `source_date` | 对应来源的 `published_at` 日期部分或 `retrieved_on`，不是本次编辑日期 |
| `amount` / `currency` / `period` | 原币金额、三字母币种、时间与起价条件；金额可为零但必须有明确免费服务范围 |
| `scope` | 房型、服务和不包含项目，优惠或折算条件也要保留 |
| `not_a_city_average` | 固定为 `true`，说明这是有条件的观察而非城市均价 |

`monthly_total_budget: null` 表示缺少同人数、房型、租期和季节的完整可比月预算，绝不表示零成本。`price_observations: []` 表示未收录可用费用观察，不是免费。现有记录中的 `0` 只用于官方项目明确免费且限定白天的工位。

非空 `monthly_total_budget` 保持原有数值兼容性，但当前字段没有独立的币种、覆盖范围及总预算证据契约。检查器会提示人工复核；不能仅凭数值通过就把它用于跨城排名或视为完整月预算。

## 选择建议与候选

`seasonal_choice` 是带条件的编辑建议，不是天气预报或自动得分。`recommendation_for` 是本轮评估覆盖期，例如 `2026-10_to_2026-12`，不表示所有城市都适合这几个月入住；真正的季节条件看 `seasonal_choice`。`secondary_candidates` 只是未结构化的待补证线索，不与 27 个主记录按相同完备程度展示。

## 来源状态与日期

来源的 `used_with_limits` 表示按限制使用，`counterexample_only` 只用作反例，`discovery_only` 是筛选线索，`excluded` 不用于推荐。城市引用与价格直接来源仅使用 `used_with_limits`；这一状态并不证明它今天仍有效。API返回完整发布文字不等于看过图片、视频或所有回复，每条以 `read_scope` 为准。

`published_at: null` 表示发布时间未记录或未知，不能用采集时间补造发布时间；已知时间保留原有精度与时区。`retrieved_on` 记录该来源获取或核读日；重新获取主帖不等于重读评论，明确沿用的旧评论另记 `comments_reviewed_on`。评论核读日不能晚于该条获取日；已知原帖日期时，也不能早于原帖发布日期。这里只比较记录的日历日期，不推断同一天内的阅读先后。

可选的 `review_after` 与 `review_reason` 是维护者设置的下一次复核日期和原因，不是来源被判为失效的日期。检查器在日期到达时提醒；应回到官方原文核读并留下新记录，不自动把编辑用途改成“当前可靠”。天气快照过了预报窗口仍可证明历史事件，不能据此判断今天的街区状况。

## 一次复核怎样落到数据

1. 从检查器的 `WARNING`、读者纠错或计划复查中，定位城市、来源 `id` 和需要回答的问题；没有读原文前保留“待复核”。
2. 打开官方原文或公开原帖，记录实际读取日、适用对象、价格或政策条件，以及正文、媒体、评论各自读到的范围。页面不可达或只读到摘要时，如实记录缺口。
3. 保留旧来源与费用观察。复读同一网址得到新报价或核读日期时，在当前来源文件追加有独立 `id` 的新快照，并在来源账本记录新旧记录的关系与变化；不要直接改旧快照的 `retrieved_on`，否则旧的 `checked_on` 价格将失去对应日期。沿用旧评论时保留真实的 `comments_reviewed_on`。
4. 用新来源补充城市的 `source_ids` 与价格观察，同步目的地卡和账本，区分当前条件、历史样本与仍待核内容。`updated_on` 只反映本次编辑；未复核的资料日期不跟着刷新。发现记录错误时，在账本说明原记录、更正内容和原因。
5. 运行下方检查并逐条人工处理提醒；未复核的项目继续保留提醒，不为消除警告而推迟日期。检查通过只说明结构可用，不替代原文核实。

目前没有多批次来源索引或自动归档。检查器只读取 `data/destinations.json` 与固定的 `data/sources-2026-10-14.json`；给 `data/` 新增另一个来源 JSON 不会被自动发现或参与引用检查。现阶段把新的来源快照追加到现有来源文件，保留文件名与顶层最初批次日期。以后若拆批次，须先实现索引读取、跨文件唯一性与引用检查，再迁移数据和说明。

## 本地检查

```bash
python3 scripts/check_data.py --as-of 2026-10-22
python3 scripts/check_links.py --exclude web
python3 -m unittest discover -s tests -v
```

`--as-of` 固定检查日期，便于复现；不传时使用运行当天日期。检查不会访问外网。结构正确与事实正确分别核对；当前仍未重新核实的天气历史快照会保留复核提醒。

数据文件必须是标准 JSON；`NaN`、`Infinity` 与 `-Infinity` 即使出现在当前未使用的字段也会在载入时失败。来源 URL 仅接受不含空白、控制字符和内嵌用户名或密码的绝对 HTTP(S) 链接；查询参数中是否含认证令牌仍需人工检查。

数据检查拒绝重复 JSON 对象键、重复记录 `id`、同城重复 `source_ids`、未知字段以及不一致的引用或日期。重复对象键会在载入时失败，避免后一个值静默覆盖前一个证据。未知字段也报告 `ERROR`，防止 `review_aftr` 等拼写错误绕过复核提醒；新增字段时先说明含义，并同步检查器与回归测试，不能假定扩展字段已被理解。到期复核、过期推荐窗口和长期未编辑只报 `WARNING`，不会把历史证据自动判错。

本库只发布元数据和短摘要，没有完整原文、媒体响应、身份材料或账户信息。更新价格时保留旧来源，加入新观察，不把旧帖日期改成今天。

根目录的编辑资料与网站发布数据分别维护。改 `data/destinations.json` 不会自动更新线上 D1；涉及网站内容时，请同时标明需要同步的城市。
